# Business Requirements Document (BRD) - Human Assistance Network

## 1. Executive Summary
The proposed platform is a "Daily Life Assistance Platform" or "Human Assistance Network" designed to provide trusted, on-demand human assistance. It bridges the gap between digital task management and real-world caregiving. The core product is a **mobile-oriented app ecosystem** (User App and Helper App), supported by a **Showcase Website** where users can view service details, platform designs, and verification standards.

## 2. Product Positioning
Positioned as a trusted companion ecosystem, the platform differentiates itself from standard delivery or task apps by adding a crucial **"human care layer."** Catering specifically to individuals living alone, busy professionals, elderly citizens, and NRI families, the mobile-first approach ensures help is always just a tap away in their pockets.

## 3. Customer Benefits (Why Mobile-Oriented?)
Transitioning to a mobile-native approach provides significant and immediate benefits to the customer:
* **Instant Accessibility & Push Notifications:** Users receive real-time updates (e.g., "Helper has arrived", "Medicine purchased") directly on their lock screen.
* **Native GPS Live Tracking:** Families can monitor the live location of the helper and their loved ones smoothly via native mobile maps.
* **One-Tap Emergency SOS:** A physical or on-screen panic button that instantly connects to the Admin team and Family Circle.
* **Camera & Media Integration:** Helpers can instantly snap and send photos (e.g., of a prescription or groceries) seamlessly within the app.
* **Elderly-Friendly UI:** Native mobile apps allow for customized accessibility features (larger touch targets, voice-assist compatibility, and haptic feedback) tailored for older demographics.

## 4. Platform Ecosystem & Use Cases
The ecosystem relies on a robust mobile architecture, complemented by a promotional website.

### 4.1 Showcase Website (The Front Door)
* **Use Cases:**
  * View beautiful, structured designs detailing each service offering.
  * Learn about the "Family Circle" proposition.
  * Serve as a trust-building landing page showcasing verification processes, reviews, and links to download the mobile apps.

### 4.2 User Mobile App (The Requester)
* **Use Cases:**
  * Book a trusted helper for an elderly parent's hospital visit.
  * Track helper status and location in real-time via the native map.
  * Securely pay for services via mobile wallets (Apple Pay, Google Pay, UPI).
  * Coordinate via **"Family Circle"** (e.g., NRI children booking and monitoring care for parents in India).

### 4.3 Helper Mobile App (The Provider)
* **Use Cases:**
  * View and accept nearby tasks based on skills and availability.
  * Turn-by-turn native GPS navigation to task locations.
  * Complete multi-tier verification document uploads via the phone's camera.
  * Access emergency contacts during active tasks.

### 4.4 Admin Web Console (The Operator)
* **Use Cases:**
  * Monitor safety and detect anomalies (route deviations, task delays).
  * Manage helper onboarding, verification, and skill badge assignment.
  * Handle emergency escalations and dispatch support.

## 5. Core Services
* **Care & Companion Services:** Hospital companion, elderly check-ins, walking companion, child pickup/drop assistance, and emotional/social companionship.
* **Daily Task Services:** Grocery shopping, pharmacy pickup, document submission, queue standing, utility bill payments, and parcel delivery.
* **Health & Emergency:** Medicine reminders, SOS alerts, ambulance coordination, live caregiver tracking, and priority emergency booking.
* **Transport Assistance:** Safe cab companion, women's safety ride monitor, late-night tracking, and verified driver assistance.

## 6. Key Workflows (Flows)

### 6.1 Service Booking Flow
1. **Explore:** User opens the Mobile App and selects a category (e.g., Elderly Assistance).
2. **Request:** User provides task details (time, location, specific instructions).
3. **Matching:** The system matches the request with verified helpers nearby via mobile location services.
4. **Confirmation:** User confirms the booking and authorizes payment via native checkout.

### 6.2 Live Task Execution Flow
1. **Initiation:** Helper starts the journey; User and "Family Circle" receive a secure live tracking link.
2. **Progress Updates:** Helper updates status systematically on their app.
3. **Safety Monitoring:** AI Safety Layer monitors the route and time.
4. **Completion:** Task is marked complete; User rates the Helper and leaves a review.

## 7. Revenue Model
1. **Commission Per Task:** 15–25% fee on each completed booking.
2. **Subscription Plans:** Monthly fee for priority support, dedicated helpers, unlimited tracking, and emergency services.
3. **Corporate Partnerships:** B2B packages for employee assistance and elderly parent support.
4. **Healthcare Partnerships:** Integration with hospitals for patient transport, companion booking, and medicine delivery.

## 8. Launch Strategy
* **Initial Phase:** Focus strictly on **Elderly Assistance + Hospital Companion**.
  * *Why?* High emotional value, less competition, easier trust positioning, recurring customers, and strong word-of-mouth.
* **Expansion Phase:** Gradually introduce Grocery, Companion, Daily Help, Transport, and Medical Errands once trust and a reliable helper base are established.
